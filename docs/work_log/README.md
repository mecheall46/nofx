# NOFX 工作日志目录

本目录用于记录 NOFX AI 交易系统的开发、优化、问题分析等工作日志。

## 📁 目录结构

```
work_log/
├── README.md          # 本说明文件
├── 2025-11-25/        # 按日期组织的子目录
│   └── trading_analysis.md
├── 2025-11-26/
│   └── ...
└── YYYY-MM-DD/
    └── 主题.md
```

## 📝 使用规范

### 创建工作日志

1. **自动方式**（推荐）
   在 Claude Code 中使用命令：
   ```
   /work-log
   ```

2. **手动方式**
   ```bash
   # 1. 创建日期目录（如果不存在）
   mkdir docs/work_log/$(date +%Y-%m-%d)

   # 2. 创建日志文件
   touch docs/work_log/$(date +%Y-%m-%d)/主题描述.md
   ```

### 文件命名规则

- **目录名**：`YYYY-MM-DD` 格式（如 `2025-11-25`）
- **文件名**：使用描述性名称，不需要重复日期
  - ✅ `trading_analysis.md`
  - ✅ `stop_loss_fix.md`
  - ✅ `performance_optimization.md`
  - ❌ `2025-11-25_trading_analysis.md`（冗余日期）

## 📋 日志类型

### 1. 问题分析报告
记录系统问题的分析过程、数据证据、根因分析

**示例**：`work_log/2025-11-25/trading_analysis.md`

### 2. 修复记录
记录 Bug 修复、代码优化的实施过程和效果验证

**示例**：`work_log/2025-11-26/stop_loss_fix.md`

### 3. 功能开发日志
记录新功能的设计、实现、测试过程

**示例**：`work_log/2025-11-27/multi_exchange_support.md`

### 4. 性能优化记录
记录性能分析、优化方案、效果对比

**示例**：`work_log/2025-11-28/api_latency_optimization.md`

### 5. 每日工作总结
记录当天的主要工作内容、遇到的问题、待办事项

**示例**：`work_log/2025-11-29/daily_summary.md`

## 🎯 最佳实践

1. **及时记录**：问题分析、修复过程应在完成时立即记录
2. **数据支撑**：包含具体的错误信息、日志片段、统计数据
3. **方案对比**：记录考虑过的多个方案及选择理由
4. **效果验证**：记录实施后的效果验证数据
5. **后续跟踪**：标注需要持续观察的指标和待办事项
